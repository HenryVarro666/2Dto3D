# 问题、改进与实验交接

本目录是跨会话交接入口。**先读[问题台账](issues.md)，再读[实验索引](experiments.md)和当前计划**。历史验证细节仍以[验证记录](../verification.md)、[V3发布记录](../v3/release-notes.md)及其原始产物为证据，不覆盖或删除旧结论。

## 每次工作必须留下的记录

1. 新问题或回归先分配稳定ID；记录首次发现版本、触发输入、可复现现象、证据位置。失败尝试也记录，不能只留最终成功叙述。
2. 修改前冻结代码、输入SHA、模型revision与完整结果；区分检测、mask、几何、过滤、关联、导出和界面层。
3. 记录根因、实现选择与代价、先失败后通过的回归测试；每个修复关联问题ID。
4. 同输入复跑，保留前/后JSON、mask、GLB/PLY、配图、配置、耗时范围。单列新增误检、漏检与未改善项。
5. 只有实际验证后才更新状态；`已修复`、`部分改善`、`待验证`、`未解决`分别使用。任务成功、点数增加和单元测试通过不等于领域准确率。
6. 更新[实验索引](experiments.md)、[问题台账](issues.md)、[验证记录](../verification.md)与相应模型/运行说明；写清下一位接手者应先做什么。
7. Git保存文字、测试和实现；照片、权重、数据库、原始数组和网格继续放在ignored data/artifacts。文档用项目相对路径引用本机证据，并明确新克隆不自带这些文件。

本机实验位于`data/collections/sungrow/evaluation/runs/`。所有本地证据链接在GitHub上可能不可用，这不是已发布附件。人工gold和真实尺度缺失时不得补造指标。

## 新实验记录模板

- 实验ID／日期／关联问题ID／负责人或会话范围
- 目的及成功/拒绝标准；输入来源、同机与阶段依据、raw/normalized SHA
- baseline与after commit；依赖锁、模型revision、prompt、分辨率、SAM、阈值、设备
- 根因证据；每个假设、失败试验、修改与代价
- 回归测试RED/GREEN及完整检查命令和输出位置
- 自动结果与人工修改分开；before/after配图和可重载产物
- 改善、无变化、退步、新误检、未验证范围分别列出
- 冷/暖定义及耗时范围；是否包含上传、交付和查看器
- 输入/基线未改变、ID/节点/点数/链接校验；后续步骤和台账状态
