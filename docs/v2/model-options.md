# V2 模型选择与验证方案

资料核查：2026-10-31。当前实测是 M4 Pro、24GB、MPS 上的 SAM 2.1 tiny。RTX 5080 及其他 checkpoint 未在本项目实测。

## 先判断漏在了哪一层

| 现象 | 原因层次 | 优先处理 |
| --- | --- | --- |
| 第二箱体有检测框，却没有进入结果 | 单设备筛选 | V2 选择多设备重新识别，保留多个柜体候选。 |
| DINO有线束框，最终却没有cables | 文本类别映射 | 按原始prompt名词的token区间核对类别，不把解码出的a bundle直接丢弃，也不把残缺的##verter当完整设备证据。 |
| 线缆／箱体连候选框都没有 | 检测召回、词表或分辨率 | 手工框补漏；另测检测器、提示词与局部裁剪。单换 SAM 不会给当前检测流程自动增加框。 |
| 框内混进墙面，细线漏掉一部分 | 分割边界 | 加正负点、重新框选；对照测试更大 SAM。 |
| 三维厚度、背面或真实线缆路径不正确 | 几何与单视图信息不足 | 当前仅为外接框／类别先验示意；需要多视图、尺度依据或独立几何模型。 |

## 类别与主设备筛选

模型和检测阈值保持不变。类别按固定prompt中完整名词的token区间解析；多词片名词取各词片的最低支持，避免单独的##verter将人员误当逆变器。原始短语仍可用于诊断，bundle的恢复还需要邻近设备上下文。

单设备优先完整逆变器类别证据，再按模型分数选择；缺少该证据时可回退到尺寸可用的普通柜体。通用柜体覆盖画面超过65%，或包含明确逆变器且面积超过其1.8倍时，作为场景包络候选过滤；包含比例要求至少90%。不足画面1%的框不独立建立主设备或尺度锚点，多个设备中的小次要框仍可能保留。明确的逆变器近景不按通用大框规则删除。

这些是本项目检查型照片的启发式保护，不是设备存在性的概率证明；极近的普通柜体、远处小设备和空桥架仍需单独验证。每份结果的model.filtering记录策略版本、保护参数、过滤数量和主目标。更大的SAM不会恢复在分类或筛选阶段已经丢掉的候选。单／多设备仍受同类NMS和12组件上限约束，三维生成方式未改变。

## SAM 2.1：已提供受控大小配置

`PV3D_SAM_SIZE=tiny|small|base-plus|large` 在服务启动时选择，默认 tiny。四个大小映射到适配器中的固定官方 Hugging Face revision，客户端不能传入任意模型／目录。首次切换需下载相应权重，缓存与照片均不入库。

| 大小 | 官方参数量（百万） | 项目状态 |
| --- | --- | --- |
| tiny | 38.9 | 已在 MPS 运行自动分割和框＋正负点细化。 |
| small | 46.0 | 允许配置，未实测。 |
| base-plus | 80.8 | 允许配置，未实测；建议先在 5080 对照 tiny。 |
| large | 224.4 | 允许配置，未实测；作为质量优先的对照候选。 |

官方通用视频评测中，larger checkpoint 的质量与速度存在取舍。这支持“值得比较”的判断，不能证明光伏细线一定改善，也不能用官方 A100 FPS 推算 M4／5080 的网页响应。SAM 2 代码及权重使用 Apache 2.0；具体分发仍须保留各依赖的许可。[官方模型表及测量条件](https://github.com/facebookresearch/sam2#model-description)、[许可说明](https://github.com/facebookresearch/sam2#license)

```bash
PV3D_SAM_SIZE=base-plus make models
PV3D_SAM_SIZE=base-plus make dev
```

M4 继续保留 tiny 作为已运行的基线。交互调用缓存两张图的图像特征，后续加点可复用编码；新图／新 checkpoint／设备变化不复用错误特征。当前一次真实照片功能检查观察到首次细化约 12.0 秒（另有模型载入约 2.8 秒），加点后约 1.3 秒且缓存命中；两次调用不能代表 p95 或质量基准。

## 检测与下一代候选

| 候选 | 用途及接入判断 | 当前状态 |
| --- | --- | --- |
| Grounding DINO base | 同一开放词表检测路线的更大候选，用于比较缺框的召回与误检。官方有 Transformers 接口；需独立固定 revision、回归阈值、耗时和许可证。 | 当前仍为 tiny，base 未接入。 |
| SAM 3／3.1 | SAM 3 可按文本概念／示例找多个实例，并支持视觉提示；有机会替代部分检测＋分割链路。官方 3.1 更新重点包括多对象视频跟踪，单张光伏照片收益仍需实测。 | 未接入，不是 SAM 2 的大小开关。 |

[DINO base 官方模型卡](https://huggingface.co/IDEA-Research/grounding-dino-base) 标注 Apache 2.0。[SAM 3 官方安装与介绍](https://github.com/facebookresearch/sam3#installation) 当前要求 Python ≥3.12、PyTorch ≥2.7、CUDA ≥12.6，下载权重需申请访问，采用独立 SAM License。应在单独环境验证 API 和 5080 实际显存，不能假定当前锁定环境直接兼容，也不能声称已有 MPS 路径。[SAM 3.1 更新](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md)、[SAM 许可](https://github.com/facebookresearch/sam3/blob/main/LICENSE)

SAM 3 与 SAM 3D Objects 是不同任务／项目，升级分割不会自动恢复精确三维、内部结构或完整 BOM。

## 如何选择默认模型

先制作独立实物的可见区域真值，重点覆盖线缆、第二箱体、细杆、反光、遮挡和远景；同实物的裁剪与多张照片必须处于同一数据分区。当前样图只用于功能复现。

1. 固定同一图像、提示框和正负点，比较 tiny／base-plus／large；分别统计掩码 IoU、边界 F1、断裂／粘连和达到可接受区域所需点击次数。
2. 检测器单独比较候选召回、误检、计数，保持分割器固定；记录单／多设备筛选前后的候选，避免把规则变化算成模型提升。
3. 在 M4 与 5080 分开记录模型版本、环境、实际显存／内存峰值，冷载入、新图编码、同图加点和端到端时间；样本与重复数充足后再报 p50／p95。下载时间另列。
4. 检查后端持久化、三语草稿、稳定组件 ID、重建和 GLB 选择是否仍正确。质量改善且交互延迟／内存可接受后，才更换默认值。

建议顺序是先用 V2 取得可靠的人工修正反馈，再在 5080 对照 base-plus／large；若主要问题仍是缺框，优先比较 DINO base 或 SAM 3。当前不训练模型，不承诺尚未测得的提升。
