## 交付行为

- 单图工作区与多视角工作区可切换，已载入的工作区状态保留；有任务或标注草稿时禁止切换，避免隐藏尚未结束的编辑。
- 多视角组包含同一设备的 2–8 张重叠照片；用户先选择／移除照片，再明确启动融合。重复 ID／相同输入哈希拒绝，照片仍按 V2 校验与方向归一化。2 张是接口下限，推荐 3 张以上；不能保证少量照片足够重建细线。
- VGGT 联合推理相机与深度，在统一坐标中反投影；按有效图像区域、有限深度、置信度筛选，再按体素合并多视角点。保存相机、预处理映射和模型版本，不能把多张独立单目点云叠放冒充融合。
- 每张照片继续用真实 Grounding DINO／SAM 识别组件；由组件区域选择对应三维点。跨图关联是几何与类别启发式候选，明确提示用户核对，不保证每根电线或完整 BOM。
- 照片缩略图可切换；照片、组件列表和三维点云联动选择、隐藏和隔离。背景点可独立显示。GLB／PLY／JSON 可下载，均标相对尺度。
- 每个视角保留框选、SAM 正负点、重框、撤销、确认／仅框回退。人工重建保留观察 ID、组件 ID、掩码证据；复用已保存的多视角几何，不重复运行 VGGT。
- 可把观察关联到已有组件，或分离成独立组件，修正自动跨图合并。改名／类别传播到该组件的各视角观察；框／掩码只改变当前观察。
- 三语切换不重跑任务或清空草稿。停止等待不承诺终止已排队推理；真实失败保留阶段与可编辑资料，不生成虚假点云。

## 实现选择（由实现方确定）

保留 API 的 NumPy 2.x。VGGT 官方包要求 NumPy <2，因此置于 `services/multiview/` 的独立锁定环境，通过单个子进程调用；仍占用现有有界单 worker，不能同时占用多个模型推理槽。代码固定官方 commit，权重固定 Hugging Face revision；不执行远程自定义模型代码或加载任意客户端路径。

模型为公开的 `facebook/VGGT-1B` 研究 checkpoint，原始权重 CC-BY-NC-4.0；商业 checkpoint 另行申请且不在本次自动处理范围。当前为私人研究原型，不宣称可直接商业部署。默认输入边长 336（14 的倍数），配置允许 224／336／518，越低可能丢失细节。CUDA／MPS／CPU 由服务启动配置选择，耗时不作保证。

新增 `/api/captures` 与 `/api/multiview/jobs`，不改变旧 `/api/jobs` 的单图契约。新 SQLite 表仅新增。新结果保存 `representation='fused_point_cloud'`、`metric_scale_status='unknown'`、逐图观察、全局组件、点数、背景点数、相机诊断及几何来源任务 ID。

点云保留 RGB；语义类别及掩码关联不等同于工程物料识别。使用同一设备照片是用户输入约束，模型无法可靠证明任意两张照片属于同一实物；低重叠／低视差诊断提示复拍。毫米测量、生成隐藏结构、逐根电线连接关系、站级重建不在本次范围。
