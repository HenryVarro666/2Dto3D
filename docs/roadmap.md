# 设备类别扩展路线图

日期：2026-10-30。本文件记录已确认的扩展方向；各阶段均处于计划状态，应用代码尚未实现。

用户已确认：**第一期先做好组串式逆变器及外部安装结构，之后扩展到箱变、变压器等多类设备。** 以下阶段划分、组件例子和验收方式是实现建议。

## 一期：组串式逆变器及外部安装结构

先处理一张照片中选定的一台设备。初始组件包括主机外壳、可辨认的安装支架、成组线缆；支撑立柱可作为上下文。实际组件范围按照片确定，不能为满足固定数量生成被遮挡的零件。

一期完成顺序：

1. 在 RTX 5080 上验证检测／分割、参数化结构示意和 GLB 查看，测量到首个可旋转场景的总时间。
2. 完成组件树、点选与隐藏，保存人工纠正并导出有组件 ID 的 GLB＋JSON。
3. 在现有显存条件下单独验证后台几何细化，记录成功组件、未分解整物和失败情况。

通过条件是支持样本中可见组件对应正确、示意布局有助理解，并在声明的运行条件下满足 10 秒首屏目标。后台逐组件细化另行验收，不能用整物网格替代。具体实验与停止条件见 [计划书](plan.md)。

## 二期：箱变／预装式变电站

新增设备类别及词表，围绕外壳、可见门板、通风或散热外部构件、基础／底座建立示意规则。这些是候选标注类别，须由真实样本核对，不表示每台设备都具备所有组件。

需要增加近／远、正／侧视和遮挡样本，处理大型箱体的透视、重复面板及密集外部结构。外观照片不证明内部变压器、开关柜或分舱配置；只有图纸、已核实型号资料或其他独立证据支持时，才增加相应信息，并记录来源。

这一阶段继续以单台设备为对象，不把整座场站重建同时纳入。

## 三期：独立变压器

补充可见壳体、外露套管、外部散热构件及底座等候选类别，按干式／油浸等实际样本差异设计配置，不能套用单一外形。重点验证细长部件、重复散热片、反光和遮挡；部件存在但分辨率不足时保留“无法辨认”。

先提供外部结构示意；铭牌参数、内部绕组和真实电气连接不由外观补全认定。尺寸与 CAD 支线仍要求独立依据。

## 后续：更多设备与多设备场景

根据用户样本逐步增加配电柜、汇流箱等类别。单设备能力稳定后，再考虑同图多设备的实例关联、跨照片设备匹配和站级布局；这将需要独立的场景级数据与验收。

## 如何扩展代码与数据

后续代码建议将设备差异放在 `equipment_type` 和独立配置中，例如 `string_inverter`、`compact_substation`、`transformer`；未知类别保留 `unknown`。每类配置包含识别词表、组件层级、基本体映射和标注规则，名称暂定，尚无配置文件。

共用上传接口、组件 ID、字段级证据、相对坐标和 GLB 导出契约。查看器读取场景与组件清单，避免把逆变器专用类别写死在界面。后台几何适配器和设备类别分别管理，使更换模型不改变业务组件 ID。

每进入一个新类别：

- 新增独立实物样本与人工确认的可见组件；10–12 个独立目标可作为探索起点，不代表统计充分性。
- 按物理设备分组留出测试数据；同设备的照片、裁剪和视频帧不得跨分区。
- 分别检查类别、计数、掩码、二维—三维对应及完整首屏时间，单列新类别失败。
- 回归已有类别，确认新增识别规则不会把原有组件强行归入新类，也不会影响原有时延。

扩展顺序已确定，但新增数据能否取得、具体组件划分及各期资源和排期仍需按实际情况收敛。详见 [硬件方案](hardware.md) 与 [数据说明](../data/README.md)。
